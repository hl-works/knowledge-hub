What is a "skill"
(and a hook, a subagent, a plugin)?

When you're explaining the same procedure to Claude for the third time, that's a skill in disguise. A skill is a procedure written in a folder, which Claude loads on its own when the situation calls for it. Around it, three words that keep coming up: hook, subagent, plugin. Here's what each one does, and which to pick.

By Hugo Lahutte · September 1, 2026 · ~6 min read

In 30 seconds

  • A skill = a folder with a SKILL.md file (the procedure, in text) and sometimes scripts. Claude loads it on demand, when your request matches. It's packaged know-how, portable from one tool to another.
  • A hook = a script that fires automatically at a specific moment (before a command, after a change). Deterministic: it doesn't "think," it checks or blocks.
  • A subagent = a Claude delegated to a subtask, with its own context. A plugin = the package that installs skills, hooks, subagents and connectors in one go.

1. The problem: the procedure you keep re-explaining

Publishing an entry on this site takes about twenty steps: the page, its English twin, the journal index, the homepage teaser, the sitemap, the llms.txt, the search index, the counters, a consistency check. The first six times, I explained it to Claude at the start of the session. The seventh time, I realized the problem wasn't Claude: it was me keeping the procedure in my head instead of writing it down.

The CLAUDE.md takes care of general rules (tone, principles, pitfalls). But a twenty-step procedure has no business there: it would weigh down every conversation, including the ones that don't need it. I needed a place for procedures, loaded only when useful. That's the skill.

2. The skill: a procedure in a folder

A skill is a folder containing a SKILL.md file: at the top, a name and a description (that's what Claude reads to decide whether the skill applies to your request); below, the procedure in plain text, with its rules, its examples and its guardrails. Optionally, scripts or reference files alongside. Nothing else.

Three skills do the bulk of my work:

  • kh-post-brief — at the end of a session, with any AI, produce the brief for a journal entry: title, vertical, author, tags from the whitelist, status, sections (context, what was done, what was hard, stack, what it illustrates), visuals to attach, and the sanitization guardrails (no secrets, no sensitive financial figures, no internal app URLs). I paste the brief into Claude Code, which publishes the FR + EN entry and all the cross-linking.
  • brain — read, search and update my Brain, with a strict write gate: read freely, write only on explicit instruction ("note that in my Brain"), never turn a discussion into a write.
  • wiki-capture — the end-of-session ritual: the session entry and the update of the reference pages.

The property that matters: a skill is portable. The text of kh-post-brief is written to be pasted into ChatGPT or Gemini at the end of a session; the AI returns the brief, and Claude Code publishes. A well-written skill survives a change of tool. And since summer 2026, the Claude Cowork app even lets you teach a skill by recording your screen while narrating: Claude turns it into a reusable skill, without writing a line.

3. The hook: an automatic reflex

A hook is a script that fires automatically at a specific moment in Claude's work: before a command is run, after a file has been modified, when the conversation gets compacted, when a session ends. The fundamental difference from a skill: a hook doesn't think. It checks, blocks, formats, logs — deterministically, every time, no exceptions.

Useful examples for a merchant: refusing any command that would push code straight to production; running a consistency checker after every change to a data file; forbidding a file containing a secret from being added to the repo. What I used to entrust to a CLAUDE.md rule ("never merge the whole branch") can become a hook that makes the mistake physically impossible. A rule gets read; a hook gets executed.

Honest limit: hooks run in Claude Code (the terminal, or its web and desktop versions). In a Chat conversation or on mobile, they don't exist — hence, in my setup, a duplicate instruction rule for whatever has to work everywhere.

4. The subagent: delegating a subtask

A subagent is a Claude that the main agent hands a subtask to, with its own context, its own instructions, sometimes its own tools. It works — in the background by default, since summer 2026 — and returns a result. Three uses:

  • Parallelize: translate twenty pages, audit ten files, check five sources at the same time.
  • Isolate context: a heavy read (a long document, an entire repo) doesn't clutter the main conversation; only the conclusion comes back up.
  • Specialize: a "reviewer" subagent with adversarial instructions, a "verifier" subagent that only confirms or refutes.

Workflows (available in Claude Code since June 2026) are the layer above: a small script that orchestrates several subagents deterministically — a review per dimension, then a check of each finding, for example. Useful, but reserve it for tasks that deserve a dozen agents. The default reflex is still: start without.

5. The plugin: the package

A plugin bundles skills, subagents, commands, hooks and connectors into a versioned package, installable in one command. It's the way to share complete know-how with a team — or to install it at home from a marketplace. The code security checker I use before every delivery is a plugin; my publishing pipeline will become one the day someone other than me has to publish here.

6. Instruction, skill, hook or connector: which to choose

7. And without a terminal?

Skills aren't reserved for developers. Claude Cowork (the desktop app, also on the web and on mobile) installs them from a marketplace and loads them into ordinary office work: preparing a deck, going through a file, running a routine. And learning by screen recording is the simplest way there is to turn know-how into a procedure: you do the task once while narrating, Claude writes it up.

My advice for getting started: take the procedure you explain most often — not the most impressive, the most repeated — and write it in ten lines with a filled-in example. If Claude gets it right three times in a row without your help, it's a skill. If not, the procedure wasn't clear, and you just learned that.
