HL OS: five building blocks, one foundation — the map of the system

Claude · HL · September 1, 2026 · Perso
stratagentinfraen-coursPerso

Context

Since June, I'd been building several things in parallel without naming them together: a magazine-publisher ERP built in five days (HF-OS), a mail-and-tasks building block, a shared AI layer, a content machine, a private brain, and — since late August — Growth, the action queue that replaces ten dashboards at Cobra. Each had its spec, its decisions, its plan. What was missing was the map: how it all fits together, what's shared, what must never be.

On September 1, while writing the Growth building block into the Brain, the map drew itself. What I'm building has a name: HL OS. Not a collection of scripts — an operating system, in the sense of “what everything else runs on”.

What was done

  • The foundation, named: a shared database (inherited from HF-OS — a single application that serves the dashboard, the admin and the API), a shared AI layer (writing in my voices, embeddings, a router that picks the model by tier and logs every call, secrets encrypted server-side), identity and permissions (allowlist login, roles), and an action log.
  • Five building blocks, each with its boundary: Zéro (mail + tasks, the source of daily signal), Knowledge (the Brain and its index — the “inbound” direction), Content Machine (one capture, N destinations — the “outbound” direction), Growth (measure, reconcile, diagnose, recommend, prepare an action) and AI Core (Socle IA) (the other building blocks call it; they don't reimplement it). Growth measures and recommends; the Content Machine makes and publishes; Knowledge keeps. Three decisions from the same day set these boundaries: Knowledge's “outbound” direction is attached to the Content Machine; Growth covers organic and paid on the measurement side but never publishes; the two share campaign identifiers so that D+3 and D+14 results feed the next batch.
  • One core, several contexts: Cobra and Haute Fidélité share the intelligence, never the accounts, the secrets, the data or the operating rules. The first Growth instance runs for Cobra; the Haute Fidélité instance will reuse the core as an isolated context.
  • The single flow of an action: request → analysis → preview of the change → validation → execution → log → measurement. Automatic reads and refreshes; writes to Shopify, Odoo, the ad platforms, email or social networks require validation as long as no finer-grained permission exists. The assistant never gets more rights than the person talking to it.
  • The immediate priority, on record: the reliability of audience measurement. Observed coverage against real orders is too low to move a budget on that signal alone; a seven-day daily watch, read-only, compares the store, the ERP and analytics without touching the tracking.

What was hard / unexpected

Resisting the urge for a separate “decisions” folder. Each building block and each entity carries its own dated Decisions section; that's where the trade-off lives, not in a buried session. The stance holds as long as decisions stay easy to find — it's written as a switch-over criterion, not as a certainty.

Not freezing a snapshot into truth. Growth's state as of September 1 (what's connected, what's reliable, what isn't yet) is recorded as a dated block, with the explicit instruction never to copy those values as permanent. A stale brain is worse than an empty brain; a stale table of numbers, even more so.

The word “OS” is a big one for an outfit my size. I own it: the day I started calling this an OS, I stopped thinking of it as a collection of scripts, and the boundaries between building blocks became decisions rather than accidents.

Stack

A headless CMS and a web framework in a single application, PostgreSQL, hosting as a persistent process; Cobra's internal apps hub for the Growth instance; the Claude API through the AI Core router; the Odoo, Shopify, Google Analytics, Ads, Search Console, Merchant Center and Brevo connectors, plus the social networks' native APIs on the measurement side; Telegram as the Content Machine's cockpit; the Brain in OKF format as memory.

What it illustrates

The value isn't in one more tool. It's in a layer above the tools that reads everything, reconciles the facts, proposes and keeps the trail — and in the boundaries that make that layer safe: a shared core, isolated contexts, validation before any write. The hard work wasn't the code: it was deciding which source to believe (Odoo carries what was actually sold, Shopify the web flow, the ad platforms their self-reported attribution) and preventing misleading reconciliations. The AI typed the code; the trade-offs stay human. The full guide: What is HL OS.
