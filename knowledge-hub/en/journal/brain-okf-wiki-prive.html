The Brain: my private wiki in OKF format, read by all my Claudes

Claude · HL · August 22, 2026 · Perso
docmetastraten-prodPerso

Context

A tweet, on a Friday evening in August: an open-source plugin for the Open Knowledge Format, the specification Google Cloud published in June that formalizes Karpathy's “wiki for LLMs”. Two questions behind it: can I put everything I do into a wiki, and can a single wiki serve both my Claudes — the personal account and the Cobra account — plus another assistant now and then?

The “Knowledge” building block of my system had already been specified in late July, with a PostgreSQL database and a vector index as storage, and a homemade MCP server to plug it into three clients. So the real question was: does OKF replace that plan, or slot into it?

What was done

  • The brain bundle: a private git repo, seven folders — entities (the group's structures), building blocks (the systems under construction), projects (what has an end), personal (always private), method (prescriptive), notes (revisable), sessions (the raw journal) — a root index.md and a log.md for structural changes.
  • The front-matter convention: OKF's standard fields (type, title, description, tags, date) plus two homemade ones — confidentialite (prive or publiable), which makes the public/private guardrail machine-readable, and auteur (me, Claude HL or Claude Cobra), without which it's impossible, six months later, to judge how reliable a page is.
  • The Knowledge building block, revised: Markdown becomes the source of truth; the database and the vector index become a derived index, rebuilt from the files — and pushed back until navigation is no longer enough.
  • The capture ritual: a skill that, at the end of a session, writes the sessions/ entry and proposes targeted edits to the reference pages it touched. Then, the next day, the shell rule (a shell being an empty placeholder page: it announces itself as empty and asks questions; we never invent its contents), the notes/ folder with its status (draft, held, revised, abandoned) and its mandatory “what could take this apart” section, and a small linter that checks all of it before every commit.

What was hard / unexpected

The “OKF solves multi-client sharing” trap. It doesn't: OKF is a format, not a service. It syncs nothing, searches nothing, exposes nothing. What lets one wiki serve several Claudes is the access layer — so the MCP server was still needed… until we noticed that the GitHub connector is enough as long as the bundle stays small: agents start from the index and follow the links. Hence the MCP steps being deferred, and one sentence written in place of the step: the day “find me what we said about order dedup” no longer surfaces the right document, we build the index.

No auto-trigger possible. The idea of launching the capture automatically past a certain conversation length doesn't hold: no mechanism fires on a context threshold, and hooks only run in Claude Code — not on mobile, not in Cowork. The answer came through instruction rather than infrastructure: a CLAUDE.md rule that, when the conversation gets long, offers to close with a handoff brief and to capture.

A pleasant side effect: the item “Claude project documents have no export” disappears. Those documents natively become pages in the bundle.

Stack

OKF (Markdown + YAML front matter), git, a private GitHub repo, the GitHub connector in the Claude apps, a Python linter. PostgreSQL and pgvector deferred to the moment navigation is no longer enough.

What it illustrates

A standard format doesn't replace infrastructure, but it can delay the moment it becomes necessary — and that delay is the real win. The initial plan built the server in step 2; the GitHub shortcut covers the same need with zero lines of code, and leaves a clear signal for knowing when to build. A corollary, now a note in the Brain: writing down the switch-over criterion beats building the step ahead of time. And one conviction that governs everything else: a stale brain is worse than an empty brain. A missing document triggers a search; a wrong document triggers a decision.
