HL Consulting · Product handover · September 24, 2026

HL·OS

A connected internal operating system, AI-driven. It brings together email, the Haute Fidélité editorial back-office, ad sales, accounting, CRM, and security behind a single interface — with Jarvis as the search and controlled-action layer.

30-second read

What's actually in place

  • The foundation is in production: authentication, permissions, responsive shell, light/dark themes, Payload admin, PostgreSQL database, and Render deployment.
  • The most mature modules are email, the HF editorial back-office, basic CRM, the Qonto accounting cockpit, and security.
  • Jarvis can search the private corpus and the MCP server exposes email and invoice tools, but the full conversational orchestration is still a work in progress.
  • Webflow data has been migrated in, but images are still hosted by Webflow. The future public site and media library haven't been built yet.
  • No deployment is pending at the time of this status report: the last audited main is deployed and automated backups are green.

01 · Architecture

One product, multiple domains

The principle

HL·OS isn't a new ERP that duplicates everything. It acts as a cockpit and orchestration layer. Qonto stays the accounting ledger, Webflow temporarily stays the public site, Shopify stays the store, and GitHub stays the source for security audits.

The system centralizes what helps with decision-making: a common interface, permissions, connections, memory, work queues, evidence, and safe actions.

Current technical stack

  • Next.js 16 + React 19 + Payload CMS 3.
  • PostgreSQL Scaleway + pgvector.
  • App and external cron on Render.
  • Google login, roles, and per-section/mailbox permissions.
  • Secrets encrypted in the database; no keys in the repo.
  • GitHub CI, versioned migrations, and daily backups.

  2. IngestionSyncs · imports · cron · deduplication

  5. ValidationHuman review when in doubt or for sensitive actions

03 · Data

Completed imports

The repo doesn't version production database volumes. This list distinguishes what has been actually migrated in, what is continuously synced, and what is only read on demand.

Migrated · Webflow → Payload Haute Fidélité editorial corpus Countries, authors, brands, sections, product categories, issues, products, articles, and reviews. The import is idempotent, preserves original slugs and IDs, rebuilds relations, and converts rich HTML to Lexical. Limitation: images are still Webflow CDN URLs
Synced · Email → Payload Messages and history Ingestion of connected mailboxes via IMAP or Graph, sent and received messages, body, metadata, attachments, senders, rules, and CRM timeline. A historical catch-up is planned to fill in missing periods. Deduplicated by Message-Id · per-mailbox cursor
Synced · Qonto → Payload Clients, invoices, and accounting Qonto clients reconciled with CRM companies, historical and new client invoices, ad sales classification, supplier invoices, and transactions useful for reconciliation. Each HL entity has its own connection. Qonto remains the source of truth
Available · CSV → CRM Companies and contacts Batch CSV import, normalization, tags, company/contact linking, empty field completion, and duplicate detection by name, SIREN, VAT, email, or domain. Volume per run is not tracked historically
Initialized · Ad data 2026 advertising schedule The 2026 insertions and schedule dates have dedicated seed migrations. Ad tracking can then be corrected and enriched directly in HL·OS. One-time seed, versioned in migrations
Continuous ingestion · Sources → Brain Knowledge Hub and emails Published Knowledge Hub content and stored emails are chunked, deduplicated, vectorized, and indexed in PostgreSQL/pgvector. Each chunk retains its source provenance and email ACLs are re-applied in Jarvis. Daily job · semantic search available

What's connected without being "imported"

Shopify (orders and customers), Brevo (templates, campaigns, and deliverability), and Agent Security (GitHub audits) are accessed via their APIs. HL·OS displays and uses this data, but doesn't try to maintain a full local copy of these systems.

04 · Automation

What runs on its own

Seven business jobs

  • Regular mailbox sync.
  • Historical message catch-up.
  • Automatic triage and noise cleanup.
  • Accounting detection and email/Qonto reconciliation.
  • New Qonto invoice sync.
  • Automatic follow-ups via Brevo.
  • Knowledge corpus ingestion.

Operations

An external Render cron wakes the queue every five minutes. This replaces the built-in scheduler, which could silently freeze under Next.js.

The system has a protected route, a queue visible in the admin, database migrations, and nightly backups. What's still missing is a single business-facing screen that clearly shows: last run, result, errors, volume, and how to retry.

05 · Gaps

What isn't finished yet

Product priority Agents & executions The route exists but remains a "coming soon" page. It needs a human-readable agent log: proposed action, evidence, confidence level, validation, execution, result, and retry capability.
Data priority Import registry The tools work but the history isn't centralized. Bertrand shouldn't have to read logs to find out which source was imported, when, and with how many creates, updates, duplicates, and errors.
Webflow blocker Media library Editorial images are still on Webflow. Before any cutover, you need object storage, a Media collection, WebP/AVIF conversion, responsive variants, metadata, and re-linking to content.
Phase 2 Haute Fidélité public site The apps/web directory is still a skeleton. Identity, templates, static rendering, search, structured data, and the Webflow redirect plan all remain to be built.
Accounting P7 Supplier portals The registry and collection engine exist, with a first Meta adapter. What remains: stabilizing Meta, adding Google Ads, and industrializing monthly collection without exposing credentials.
Operational quality Metrics & alerts Confidence indicators are needed: email triage accuracy, auto-reconciliation rate, anomalies, lagging syncs, and corpus quality. Right now, the capability exists more than its measurement does.

06 · Bertrand handover

The development brief

Recommended mission

Make what exists reliable and observable before adding a big new module. The foundation, models, and most connectors are already there. The best contribution isn't rebuilding screens — it's turning scattered functions into understandable, measurable, and recoverable workflows.

Batch 1 · Mapping Get the project running Install locally, run migrations on an empty database, log in, browse the routes, read the roles, and identify which external services can be mocked. Document only the gaps you actually find. Deliverable: reproducible environment + route matrix
Batch 2 · Observability Build the execution center Replace the /ia placeholder with a live jobs and agents view: status, source, start/end, counters, readable errors, useful logs, manual retry, and a link to the relevant business object. Deliverable: any execution is understandable without opening Render
Batch 3 · Imports Unify synchronizations Create a shared registry for Webflow, Qonto, email, CRM, and Knowledge: last success, next run, volumes, cursor, failures, retry, and idempotency. Don't move the existing engines. Deliverable: single source of truth for data state
Batch 4 · Media Get images off Webflow Set up object storage, Payload Media, variants, metadata, idempotent migration, and broken link checks. No public cutover until this batch is fully validated. Deliverable: content independent of Webflow
Batch 5 · Accounting Close the exceptions Stabilize supplier portals, enrich reconciliation evidence, and measure what passes automatically. Keep the rule: human review when in doubt, no payment capability. Deliverable: measured automation, actionable exceptions
Batch 6 · Jarvis Go from searching to acting Connect existing capabilities into a single experience: retrieve evidence, prepare the action, display permissions, and ask for explicit validation when required. Keep logs and idempotency throughout. Deliverable: one action traceable end to end

Non-negotiable guardrails

  • Never mix Cobra and HL entities in accounting.
  • Qonto stays the ledger; HL·OS supervises and prepares.
  • No automatic payments or security merges.
  • Every external action must be logged and replayable without duplicates.
  • ACLs are enforced server-side, never just hidden in the UI.
  • Secrets stay encrypted and never flow through logs or the front end.

Definition of "done"

  • Typecheck, lint, tests, and production build all green.
  • Responsive light/dark test on modified routes.
  • Happy path, missing config, and API failure all covered.
  • Execution status visible without technical access to Render.
  • No silent data or permission changes.
  • Documentation updated in the same place as the code.
