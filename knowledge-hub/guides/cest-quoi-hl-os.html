C'est quoi HL OS :
un système d'exploitation pour piloter un groupe avec l'IA

Un magasin, un magazine, une marque, une structure perso — et dix outils qui ne se parlent pas. HL OS, c'est le nom que je donne à ce que je construis depuis juin 2026 pour piloter tout ça avec l'IA : un socle commun, cinq briques, et une règle — l'IA propose, l'humain valide. La carte, sans jargon.

Par Hugo Lahutte · 1er septembre 2026 · ~8 min de lecture
HL OS agent strat Claude Code

En 30 secondes

  • HL OS = un socle commun (une base de données, une couche IA, l'identité et les droits, un journal des actions) + cinq briques qui s'y branchent : Zéro (mail et tâches), Knowledge (le Brain), Content Machine (publier), Growth (décider), Socle IA (rédiger, chercher, sécuriser).
  • Un cœur, plusieurs contextes : Cobra et Haute Fidélité partagent les moteurs, jamais les comptes, les données ni les règles.
  • Chaque action suit le même flux : demande → analyse → aperçu → validation → exécution → journal → mesure. Lire est automatique ; écrire est validé.

1. Pourquoi un « OS »

Mon quotidien, c'est Odoo pour les ventes, la marge et le stock ; Shopify pour les boutiques ; Google Analytics, Ads, Search Console et Merchant Center pour la visibilité ; Brevo pour l'e-mail ; les réseaux sociaux ; une boîte mail par structure ; un magazine à fabriquer. Chaque outil sait produire son tableau de bord. Aucun ne répond seul à la question qui compte : qu'est-ce qui mérite mon temps aujourd'hui ?

Jusqu'en 2025, la réponse était « embaucher, ou acheter une suite ». En 2026, l'IA change l'échelle de ce qu'un dirigeant qui sait ce qu'il veut peut faire construire. J'ai donc arrêté d'empiler des outils et commencé à bâtir la couche au-dessus — celle qui lit tous les outils, rapproche les faits, propose des actions et garde la trace. Un système d'exploitation, au sens propre : ce sur quoi tout le reste tourne.

Le mot est un peu grand pour une structure de ma taille. Je l'assume : le jour où j'ai commencé à appeler ça un OS, j'ai arrêté de le penser comme une collection de scripts.

2. Le socle

Tout repose sur quatre choses partagées :

  • Une base de données commune, héritée de HF-OS, l'ERP de presse que j'ai bâti en cinq jours en juin : une seule application (un CMS headless + un framework web + PostgreSQL) qui sert le tableau de bord, l'administration et l'API. Les briques ne réinventent pas un stockage : elles s'y branchent.
  • Une couche IA commune — le Socle IA : rédaction dans ma voix (plusieurs voix, en fait : le magazine, moi en première personne, le carnet de voyage), embeddings pour la recherche, un routeur qui choisit le modèle par palier (petit, grand, secours) et journalise chaque appel, et un motif de secrets chiffrés côté serveur — jamais dans le code, jamais dans le Brain.
  • L'identité et les droits : connexion Google restreinte à une liste blanche, rôles, et la règle qui gouverne tout — l'assistant n'obtient jamais plus de droits que la personne qui lui parle.
  • Un journal des actions : chaque écriture laisse une trace exploitable, idempotente quand le connecteur le permet.

3. Les cinq briques

Une brique, c'est un périmètre, une spécification vivante, un plan de développement avec des critères de succès (« on saura que c'est bon quand… ») et une section Décisions datée. Les cinq :

Growth — de dix tableaux de bord à une file d'actions

La brique la plus avancée. Elle récupère automatiquement les faits disponibles (Odoo, Shopify, Analytics, Ads, Search Console, Merchant Center, contrôles de santé web, e-mail, réseaux), les rapproche, et propose quelques actions classées par impact, confiance, effort et risque. Une page d'accueil courte, une barre unique pour poser une question ou préparer une action, et les vues expertes derrière, comme preuves. Une absence de donnée s'affiche comme telle — jamais un zéro silencieux. Détail dans l'entrée de journal.

Content Machine — une capture, N destinations

Elle ne produit pas du contenu, elle transporte une présence : quelques photos, un vocal, à un lieu, une heure, par une personne identifiée — et la machine propose les rendus (post, article, page papier) vers les bonnes destinations, sans jamais publier seule. Guide dédié : Content Machine.

Knowledge — le Brain

La mémoire durable, au format OKF, lue par toutes mes IA. Guide dédié : C'est quoi un Brain.

4. Un cœur, plusieurs contextes

La décision d'architecture la plus importante, prise dès le début : Cobra et Haute Fidélité partagent l'intelligence, jamais les comptes, les secrets, les données ni les règles opérationnelles. La première instance de Growth tourne pour Cobra ; une instance Haute Fidélité réutilisera le même cœur avec ses propres comptes, données et objectifs — un contexte isolé dans HL OS. La Content Machine fonctionne pareil : un contexte (la provenance — où, quand, pourquoi) n'est pas une destination (où ça publie), et un contexte se déploie vers plusieurs destinations.

Le bénéfice n'est pas que technique. C'est ce qui permet de faire tourner un compte pro et un compte perso, un Claude Cobra et un Claude HL, sans jamais mélanger deux périmètres dans une base lue des deux côtés.

5. Le flux d'une action

Quelle que soit la brique, une action qui touche au monde réel (un prix, un stock, une campagne, un e-mail, une publication) suit le même chemin :

Demandeune question, une intention
→auto
Analysefaits, sources, fraîcheur
→auto
Aperçuce qui va changer
→humain
Validationun bouton, une personne
→auto
Exécutionvia le connecteur
→auto
Journal + mesureavant / après, réinjecté

Lire et rafraîchir peuvent être automatiques. Écrire vers Shopify, Odoo, une régie publicitaire, l'outil d'e-mail ou un réseau social reste en validation requise tant qu'une permission explicite plus fine n'existe pas. Et une recommandation sans mesure après exécution ne ferme pas la boucle : elle n'est pas « apprise ».

6. Où ça en est (septembre 2026)

Instantané daté · 1er septembre 2026

  • Growth — en production pour Cobra depuis le 1er septembre : accueil action-first, barre principale, vues de preuve, lectures de toutes les sources branchées. Priorité du moment : fiabiliser la mesure d'audience avant d'autoriser toute recommandation de déplacement de budget. Particularité : cette brique a été construite avec ChatGPT et Codex, Claude n'intervenant qu'à la marge (le récit et l'architecture).
  • Content Machine — cahier des charges v2 (30 juillet), socle en place ; le pivot du 1er septembre unifie capture terrain, repurposing magazine et « publie cette idée » en un seul système. Prochaine étape : la capture en moins de dix secondes, puis un premier rendu Instagram. Échéance : le salon Haute Fidélité, fin septembre.
  • Knowledge / Brain — en place depuis le 21 août ; lecture par connecteur GitHub ; index de recherche repoussé jusqu'au signal.
  • Zéro et Socle IA — en cours ; les spécifications migrent dans le Brain.

Cet état est un instantané, pas une vérité durable : les chiffres et statuts vivent dans les outils et dans le Brain, jamais recopiés ici comme permanents.

7. Ce que ça illustre

Trois choses, que je crois transférables à n'importe quelle PME :

  • La valeur n'est pas dans un tableau de bord de plus. Elle est dans le fait de pouvoir cesser d'ouvrir dix interfaces pour reconstituer une situation — et d'avoir une file d'actions avec leurs preuves.
  • Le travail difficile n'était pas le code. C'était de décider quelle source croire (Odoo porte le réalisé, Shopify le flux web, les régies leur attribution déclarée) et d'empêcher les rapprochements trompeurs. L'IA a frappé le code ; les arbitrages restent humains.
  • Construire plutôt qu'attendre un devis, quand le métier est spécifique et que le coût de la customisation s'effondre. Le cœur de Growth a été cadré un week-end et mis en production le mardi — construit, pour cette brique, avec ChatGPT et Codex plutôt qu'avec Claude. La question « faut-il encore acheter ? » se pose désormais pour la couche de pilotage, pas seulement pour l'ERP.
