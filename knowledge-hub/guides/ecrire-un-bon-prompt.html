Bien parler à l'IA en 2026 : du prompt au brief

Un bon prompt fait une bonne réponse. Un bon brief fait un bon travail — quand l'IA enchaîne les étapes toute seule, ce que tu écris avant compte plus que jamais. La recette qui tient, ce qui a changé, et ce qu'il ne faut plus retaper.

Par Hugo Lahutte · 31 mai 2026 · Mis à jour le 2 septembre 2026 · ~7 min de lecture
prompt méthode vulgarisation

En 30 secondes

  • La recette de base n'a pas bougé : contexte + tâche + format + contraintes, et un exemple du résultat voulu.
  • Ce qui a changé : l'IA ne répond plus seulement, elle travaille (lit tes fichiers, agit dans tes outils, enchaîne des étapes). Le prompt devient un brief : un objectif, un critère de succès, des points de vérification.
  • Le vrai levier n'est plus la phrase magique : c'est ce que l'IA sait avant ta demande. Une consigne que tu retapes est une règle qui s'ignore ; une procédure que tu réexpliques est un skill qui s'ignore.

1. La recette de base (toujours vraie)

Un prompt, c'est la consigne que tu écris à l'IA. Rien de technique, mais c'est ce qui change le plus une réponse : la même IA rend une bouillie générique ou un livrable propre selon la façon dont tu demandes. Pas de formule secrète — de la clarté. 2. Du prompt au brief : ce qui a changé

En mai, une demande à l'IA produisait une réponse. En septembre 2026, elle déclenche souvent un travail : Claude lit un dossier, corrige vingt fichiers, envoie un mail sous validation, tourne une heure en arrière-plan. Le mode par défaut de Claude Code enchaîne les actions sans te demander la permission à chaque étape ; Cowork fait pareil sur ton bureau. Une consigne d'une ligne qui suffisait pour une réponse devient dangereuse pour une mission.

D'où le passage du prompt au brief. Deux briques de plus, et un changement de nature pour la première :

  • Le contexte se fournit, il ne se décrit plus. Au lieu d'expliquer ton métier, tu donnes les fichiers, le dossier, le connecteur. « Voici le tableau de ventes » vaut mieux que trois paragraphes sur tes ventes. Ce qui est permanent (ton, règles, outils) n'a même plus sa place dans le prompt : Claude l'a en mémoire — et, pour un dépôt de code, dans son CLAUDE.md.
  • L'objectif et le critère de succès. « On saura que c'est bon quand… » : les 175 fiches ont un ton homogène, le script tourne sans erreur, le mail tient en 120 mots. Une IA qui agit seule a besoin de savoir quand s'arrêter — sinon elle continue, ou s'arrête trop tôt.
  • Les points de vérification. Pour une mission longue : « propose un plan avant de commencer », « montre-moi le diff avant de pousser », « une seule question à la fois si c'est ambigu ». Tu gardes la main aux moments qui comptent, pas à chaque ligne.

3. Prompt vague, prompt précis, brief

Le même besoin, trois niveaux. Le deuxième suffit pour une réponse ; le troisième est ce que j'écris quand l'IA doit livrer seule.

Et le brief, pour une mission — ici, réel, celui d'une vérification de factures confiée à Claude Code :

Objectif : vérifier que chaque facture du dossier /factures-aout correspond
à une commande Odoo. On saura que c'est bon quand : un tableau liste chaque
facture avec le n° de commande trouvé, ou « à vérifier » avec la raison.

Contexte : les factures sont des PDF ; l'accès Odoo est en lecture seule.
Règles : ne modifie rien dans Odoo ; ne devine jamais un montant.

Étapes : 1) lis le dossier et propose un plan en 5 lignes, attends mon OK ;
2) traite les factures ; 3) livre le tableau + la liste des cas douteux.
Si un point est ambigu, pose UNE question, puis continue.

Remarque ce qui manque : aucune explication de ce qu'est une facture, aucune consigne de ton, aucune règle de nommage. Tout ça est déjà su : en mémoire, dans le Brain, dans le CLAUDE.md du dépôt. Le brief ne contient que ce qui est propre à cette mission.

4. Les réflexes de 2026

  • Donne un exemple. Montrer un modèle du résultat vaut dix lignes d'explications. Pour un livrable récurrent, l'exemple finit dans un skill.
  • Demande le plan avant l'exécution. Sur tout ce qui dépasse dix minutes de travail : « propose un plan, attends mon OK ». Claude Code a un mode dédié pour ça ; ailleurs, la phrase suffit. C'est le principe « réfléchir avant d'agir » des quatre principes.
  • Une question à la fois. Autorise l'IA à te poser une question quand c'est ambigu — et interdis-lui la rafale de dix. Tu évites les réponses à côté sans te faire interroger comme au commissariat.
  • Itère sur le résultat, pas sur la phrase. « Trop long », « garde le deuxième paragraphe, coupe le reste », « montre-moi ce que tu as changé ». L'aller-retour est normal ; chercher la formulation parfaite du premier coup ne l'est pas.
  • Découpe. Une grosse mission en étapes avec un point de contrôle entre chaque. Pour un projet long, un fichier de plan que l'IA coche au fur et à mesure.
  • Dis ce qu'on ne touche pas. « Ne modifie que ce fichier », « lecture seule sur Odoo », « ne pousse rien sans me montrer ». Avec une IA qui agit, la contrainte négative compte autant que la consigne positive.
  • Ferme proprement. Quand une conversation s'allonge, demande un brief de reprise : où on en est, ce qui reste, les décisions prises. La session suivante repart de là au lieu de tout réexpliquer.

5. Les trois endroits où vit une consigne

La question à se poser devant chaque consigne : est-ce que je vais la réécrire ? Si oui, elle n'est pas au bon endroit.

Chez moi, le tutoiement, « pas de préambule », « une seule question à la fois » ou « signale sans modifier d'office » ne sont plus jamais tapés : Claude les a en mémoire, et le CLAUDE.md de chaque dépôt porte les règles du code. Je n'ai plus de fichier de consignes de base depuis que la mémoire est unifiée (août 2026). Publier une entrée de journal (page, index, sitemap, flux, traduction) n'est plus expliqué : c'est un skill. Ce guide même est né d'un brief de deux lignes, parce que tout le reste était déjà su. C'est l'idée centrale du guide C'est quoi le contexte : le prompt, c'est 20 % ; le contexte, c'est le reste.

6. Selon l'outil : Chat, Cowork, Code

  • Dans Claude Chat — la recette de base suffit, et la mémoire fait le reste : dis-lui une fois comment tu travailles, il s'en souvient. Pour un sujet récurrent, un projet avec ses documents : le contexte est fourni une fois pour toutes.
  • Dans Cowork — désigne le dossier ou le connecteur (Gmail, Drive, Shopify…) plutôt que de décrire ce qu'il contient, et dis explicitement ce qui doit être validé avant d'être envoyé ou modifié. Le guide L'IA propose, l'humain valide détaille la règle.
  • Dans Claude Code — écris un brief (objectif, critère, étapes, points de contrôle), demande le plan, laisse tourner en mode auto, relis le diff. Pour une tâche qui revient chaque jour, ce n'est plus un prompt : c'est une routine.

Le choix de l'outil lui-même est traité dans Chat, Cowork ou Code.

Pour aller plus loin

  • → C'est quoi le contexte — pourquoi ce que l'IA sait avant compte plus que la phrase.
  • → Écrire un bon CLAUDE.md — quand tes consignes deviennent permanentes.
  • → C'est quoi un skill — quand une procédure mérite mieux qu'un prompt.

Cas réels. Un brief pour que Claude travaille seul → Brief mission : vérification factures · une chaîne qui reformule chaque demande avant de coder → L'IA ne code pas ma demande, elle vérifie ce qu'elle suppose.

Échangeons

Tes prompts coincent ?

Si tu n'obtiens jamais ce que tu veux de l'IA, c'est presque toujours une question de brief — ou de contexte qui manque. Montre-moi un cas, on l'améliore ensemble. Je documente tout en public.
